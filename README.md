# dynamic-bot-weibo

微博动态源插件，用于让 dynamic-bot 订阅微博用户的新动态，并支持解析微博链接。

主项目：[dynamic-bot](https://github.com/Colter23/dynamic-bot)

## 功能

- 登录微博账号（支持二维码和 Cookie）。
- 关注、取关微博用户，可选加入关注分组。
- 检测订阅用户的新微博并推送。
- 解析微博正文和用户链接，自动补全长文。
- 登录失效时自动暂停轮询，避免反复请求。

当前版本不支持用户名搜索，添加订阅时请使用微博 UID。

## 安装

构建插件：

```powershell
.\gradlew.bat fatJar --offline
```

把生成的 `*-all.jar` 放入主程序的 `plugins/` 目录，然后启动或重启 dynamic-bot，在后台启用插件。

## 登录

在后台的“账号连接”页登录微博账号，支持二维码和 Cookie 两种方式。

推荐扫码登录，插件会保存登录跳转中获得的各域 Cookie。Cookie 登录既支持原始请求头字符串，也支持浏览器导出的 JSON 数组，或包含 `cookies` 数组的 JSON；导入后会统一保存为完整 JSON，重启后恢复。

自动续期需要新浪 SSO 的长期凭据，通常是 `login.sina.com.cn` 域的 `ALC`。只有微博主域的 `SUB/SUBP` 可以使用当前会话，但不能保证过期后恢复。需要手动获取时，在浏览器正常登录微博后，从开发者工具的 Application / Cookies 中导出 `login.sina.com.cn`、`weibo.com` 等相关域的 Cookie，包含 HttpOnly 项，再在后台导入；不要用 `document.cookie`，它读不到 HttpOnly 凭据。

每天通过 SSO 主动续期一次，遇到明确未登录时尝试恢复。设备指纹、验证码、凭据失效或续期账号变化时会停止自动换票并提示人工处理；请重新扫码，或在浏览器处理后导入完整 JSON。刷新不能保证登录永久有效，尽量保持出口 IP 和使用环境稳定。

备份、迁移和恢复请使用后台导出的完整 JSON，并同时保留 `config/` 和 `data/plugins/weibo-publisher/`。原始 Cookie 导出只包含适用于 `weibo.com` 的值，不包含其他域的长期凭据。Cookie 等同于登录凭证，备份应妥善保管，不要公开或提交到 Git。

## 配置项

微博接口比较敏感，轮询默认关闭，需要推送动态时再开启。大多数情况保持默认即可。

- `启用轮询`：是否定时检测新微博，默认关闭。
- `轮询间隔`：多久检查一次，默认 60 秒。
- `请求间隔`：连续请求微博接口之间等待多久，默认 1 秒。
- `关注分组名` / `自动创建关注分组`：关注后加入哪个分组、分组不存在时是否自动创建。
- `未登录暂停阈值`：连续未登录几次后暂停轮询。
- `补发时间窗口`：启动时是否补发最近微博，默认 0（不补发）。

## 使用建议

- 不需要推送时保持轮询关闭。
- 即使不开启轮询，现有保活任务也会每 6 小时检查会话，并在距上次成功续期满 24 小时时尝试 SSO 续期；没有 Cookie 时不请求平台。
- 链接解析遇到登录问题时会共用会话恢复流程，成功后最多重试一次。网络或服务端暂时失败按 5 分钟、30 分钟、6 小时退避，由后续请求或既有任务触发，不额外创建定时任务。
- 后台检查耗时较长时显示处理中，后续刷新会复用结果；重新登录成功后自动恢复可用的轮询，无需重启插件。
- 带视频的帖子在链接解析里会正常渲染正文（视频作为媒体卡）；如果主程序的链接解析模板包含 `{video}`，会再单独下载并发送视频文件，受主程序的“最大视频时长/视频大小上限/画质”约束。
- 不要把轮询间隔设得过短，容易触发风控。
- 出现风控或请求失败时，先暂停轮询或增大请求间隔。
- 插件通过微博关注流检测新动态，因此订阅的用户需要处于已关注状态。开启主程序的“订阅时自动关注”最省事。
